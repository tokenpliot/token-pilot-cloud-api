# #41 미귀속 비용 정의와 QUARANTINED 격리 규칙

#11에서 분리한 항목이다. 미귀속 비용 API(`GET /api/observe/ledger/unattributed-cost`)는 `QUARANTINED` 이벤트를 센다. 이 문서는 "미귀속"의 정의와 격리 시점을 정하고, 그중 수집 시 격리하는 1단계를 구현한다.

## 미귀속의 정의

**미귀속 비용 = 실제로 쓴 돈이지만 어느 예산 범위(프로젝트 환경)에도 넣을 수 없는 비용.**

#14 정책과 #17 예약은 모두 프로젝트에 **등록된 환경**을 기준으로 예산을 잡는다(`PolicyService.validateScope`는 등록되지 않은 환경의 정책을 거부한다). 그래서 등록되지 않은 환경으로 들어온 비용은 어떤 환경 예산에도 잡히지 않고, 그대로 두면 프로젝트 지출에 섞여 들어가 원인을 찾을 수 없다.

| 후보 | 미귀속으로 볼지 | 이유 |
| --- | --- | --- |
| 프로젝트에 등록되지 않은 환경 (예: `prod` 대신 `prd`, `Prod`) | **예 (1단계 구현)** | 환경 제한이 없는 키는 아무 환경 문자열이나 보낼 수 있다. 오타 하나로 비용이 예산 밖으로 샌다. |
| 이벤트를 받은 뒤 프로젝트에서 환경이 삭제됨 | 예 (2단계 제안) | 수집 당시에는 정상이었으므로 수집 시점에는 알 수 없다. 사후 대사로 처리한다. |
| 폐기·만료된 키 | 아니오 | 인증 단계에서 401/403으로 거절되어 저장되지 않는다. |
| 키의 프로젝트와 본문 `projectKey` 불일치 | 아니오 | 인증 단계에서 거절된다. |
| 키의 환경 제한과 본문 환경 불일치 | 아니오 | 인증 단계에서 거절된다. |
| 가격 미상 | 아니오 | 귀속은 확실하고 금액만 모른다. 기존대로 `UNPRICED`로 따로 집계한다. |

즉, **인증은 통과했지만 귀속 대상이 불확실한 이벤트**만 격리한다. 인증에 실패한 요청은 처음부터 저장하지 않는다.

## 1단계: 수집 시 격리 (이번 구현)

Observe 수집 v2(`POST /api/v2/observe/events`)에서 판정한다.

1. 키 인증이 끝난 뒤, 프로젝트에 등록된 환경 목록(`project_environments`)을 읽는다.
2. 요청 환경이 목록에 **정확히 같은 문자열로** 있으면 지금처럼 `PENDING`으로 기록한다. 비교는 `PolicyService`와 같이 대소문자를 구분한다(`Prod` ≠ `prod`).
3. 목록에 없으면 이벤트를 **거절하지 않고** `accounting_status = QUARANTINED`로 기록한다.
   - 거절하면 SDK가 재시도하다 버리게 되어 비용 기록 자체가 사라진다. 기록은 남기되 예산 지출에서 빼는 것이 "0달러로 위장하지 않는다"는 #11 원칙에 맞다.
   - 가격 계산, 원장 값, 정산 상태(`SETTLED`/`UNSETTLED`)는 다른 이벤트와 똑같이 남긴다. 금액이 있어야 미귀속 비용 API에 합계가 나온다.
4. 프로젝트에 등록된 환경이 **하나도 없으면** 판단 근거가 없으므로 격리하지 않는다. 프로젝트 생성·수정 API는 환경을 최소 하나 요구하므로(`@NotEmpty`) 운영 데이터에서는 생기지 않고, 환경 등록 전에 만든 기존 프로젝트를 보호하려는 예외다.

같은 이벤트의 재전송은 처음 기록을 그대로 돌려준다. 그 사이 환경을 등록해도 이미 격리된 이벤트가 자동으로 풀리지는 않는다(2단계).

### 격리된 이벤트가 나타나는 곳

| 조회 | 결과 |
| --- | --- |
| 미귀속 비용 `unattributed-cost` | 격리 건수(`quarantinedEventCount`), 최신 `ACTUAL/UNPRICED` 건수(`unpricedEventCount`), 최신 `ACTUAL/PRICED` 금액 합계(`pricedActualAmountUsd`)에 포함 |
| 지출 요약 `spend`, 판정 API의 월 지출 | 빠짐 (`LedgerSpendRepository`가 이미 `QUARANTINED`를 제외) |
| 대조 `reconciliation` | `RECONCILIATION_REQUIRED`로 분류 (`ReconciliationClassifier`가 이미 처리) |
| 수집 지연 `ingestion-lag` | `eventCount`에 포함. `unsettledCount`에는 `UNSETTLED`일 때만 포함되며, 실제 사용량의 가격이 확정되어 `SETTLED`인 격리 이벤트는 빠짐 |

미귀속 비용은 격리 이벤트의 최신 실제 원장 값만 집계한다. 가격 미상은 확정 금액 합계에 더하지 않고 `unpricedEventCount`로 따로 세므로, 합계가 0이어도 실제 비용이 0달러라는 뜻은 아니다. 기존 가격 누락 조회와 대조 분류 기준은 바꾸지 않는다.

## 2단계 제안 (팀 결정 필요)

- **사후 격리**: 프로젝트 수정으로 환경이 빠지면, 그 환경의 미확정 이벤트를 격리할지. 이미 `SETTLED`된 과거 지출까지 옮기면 지난달 보고서가 바뀌므로 범위를 정해야 한다.
- **격리 해제**: 운영자가 확인 후 `QUARANTINED → VERIFIED`(맞는 환경으로 확인) 또는 다른 환경으로 재귀속하는 API. 재귀속은 원장 값에 새 revision을 쌓는 방식(#9 설계)과 맞춰야 한다.
- **격리 사유 저장**: 지금 사유는 하나(`ENVIRONMENT_NOT_REGISTERED`)뿐이라 컬럼 없이 규칙으로 알 수 있다. 사유가 늘면 `usage_events`에 사유 컬럼(새 마이그레이션)이 필요하다.
